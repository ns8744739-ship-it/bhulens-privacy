Account & Data Deletion

Request deletion from outside the BhuLens Android app, check a request reference, and review what deletion does. Last updated: 18 November 2026.

External service readiness: The request form is implemented in the source files, but the hosted page is not yet configured with the public Google OAuth client and HTTPS BhuLens API endpoint. If setup is incomplete, the form will say so and no request will be sent. Do not send account details through public GitHub issues or comments.

Request deletion without the app

Use Google Sign-In for the Google account linked to your BhuLens account. The backend verifies the signed Google identity and account link before processing deletion. No email-only request, password, access token, or refresh token is accepted.

Check request status

The private reference is shown only when the request is submitted. Keep it private; status lookup reveals only whether deletion completed and its timestamps.

Request deletion in the app

  1. Sign in to the BhuLens account you want deleted.
  2. Open Profile & Account and choose Delete Account.
  3. Enter the email address associated with the signed-in account and confirm the request.
  4. Wait for the app to report that the request succeeded. This flow requires an authenticated app session and checks the confirmation email against the account.

This flow marks the account deleted, anonymizes selected identity fields, and revokes account access. It does not erase every associated server record or automatically wipe this device.

What deletion changes and retains

  • Anonymized: the backend clears the account email and display-name fields and replaces the Google subject with a tombstone identifier.
  • Revoked or cleared: session credentials and entitlements are revoked; Beta membership is revoked; FCM fields are cleared.
  • Retained: linked device/install and session records (including device metadata and session IP/user-agent), purchase records, village reservation/download records, bug reports and attachments, and account/security audit history remain linked to the deleted-account tombstone. A minimal external request receipt stores only a hash of the private reference, status, and timestamps; no email, Google subject, IP address, user-agent, password, or token is stored in that receipt. Retention periods, legal basis by record type, backup purge timing, and attachment cleanup are not configured or verified. Do not treat this as complete erasure.
  • Still on this device: the app-generated deviceInstallId, local Room database khetrekha.db, saved local data, map/tile caches, and other local preferences remain. Clear app storage or uninstall separately if you also want to remove local app data; this does not remove server records.

Identity verification and processing

  1. Google Sign-In proves control of a verified Google identity; BhuLens checks that its stable Google subject is linked to an active BhuLens account.
  2. A matching account is anonymized and access/session entitlements are revoked within the same database transaction that records the completed request.
  3. A random private reference is returned. Only its SHA-256 hash and completion timestamps/status are stored; the request receipt does not store an email, Google subject, IP address, user-agent, password, or token.
  4. Request status is available through this page using the private reference. A deleted Google identity cannot submit another request for the tombstoned account.

When deployed and configured, processing is synchronous. If the Google account is not linked, the request fails without deleting an account. No account is deleted based only on an email address. A completion reference is not proof that retained records or backups have been purged.
